# ece-128-lab-6
ECE 128 Lab 6. Design and Implementation of a debouncer, a sequence using a Moore state machine, and a sequence using a Mealy state machine in Verilog using Vivado

### Project Description
We were tasked with designing a button debouncer and two sequence-detecting finite state machines in Verilog, then implementing the debouncer on a physical FPGA board. To accomplish this, we built a debouncer that filters out noise from a button press by only registering the input as valid once it has stayed active for a sustained period of time. We then designed a Moore state machine that detects the sequence 1100 and a Mealy state machine that detects the sequence 1101, which allowed us to compare the two models directly: the Moore machine’s output depends only on its current state, while the Mealy machine’s output also depends on the current input. To verify the designs, we wrote a testbench for each module that exercises its key behavior, including every state transition and the asynchronous reset for the state machines, and we shortened the debouncer’s delay in simulation so the waveform stays manageable. Finally, we implemented the debouncer on an FPGA by running synthesis and implementation in Vivado, generating the bitstream, and programming the board.

### Instructions
There are 3 design files. One for a debouncer, one for a Moore state machine to create the sequence 1100, and one for a Mealy state machine to create the sequence 1101. The debouncer design files uses an input raw, to represent a button being pressed. When raw is active, a 26 bit counter starts counting by 1 every clock cycle. Once the 26 bit counter is 1111...1, and raw is still active, an output clean will be 1, indicating that the button was actually pressed to turn on whatever device and it isn't just noise. Both the Mealy and Moore state machines use behavioral modeling with parameters for each state, wires for the present state and next state, a clock, and a input for inputting the next bit in the sequence. Case statements are used to define what the next state should be based on the present state and input with the difference between the two state machines is that in the Moore implementation, the output is only based current state, while for Mealy, the output is based on the state and what the input is. However for Mealy, this really only has an impact for the last state. The testbench for the debouncer is set up to only check for 8 clock cycles before the clean output is 1, in order to get this to work properly with the design file, the design file counter must be edited to be 3 bits. This is so whoever is running the simulation has no issues with crashes due to how long the waveform would be with 26 bits. In order to implement the debouncer design to the FPGA board, one must run the synthesis, implementation, and generate the bitstream with debouncer.v set as the top module. For both the Mealy and Moore state machine testbenches, they are set up to test the both values of the input at every state, and then test the asynchornous reset at one of the states. They both test both inputs at one state before moving on to the next one.
